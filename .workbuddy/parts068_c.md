## 五、本期纠错清单（对 067 期）

### 1. ⚠️ 067 期「`Antigravity` 整站不可达、整组跳过」—— **本期首页 `200`，站点一直都活着**

**⚠️ 判据本身要收一句**：`000` 是**本报这一侧连不上**（`DNS` / `TLS` / 超时 / 出口），**不是服务器返回的状态码**。067 期其实已经写对了半句 ——「首页 `000` 不等于站点永久下线」—— 但**上一行的小标题仍写成「整站不可达」**。**本期起改口径：`000` 一律写「本报取不到」，不写「不可达」；连续期数改称「连续取不到第 N 期」。** 这不是文字游戏：`000` 与 `503` 的区别，在于**一个可能是我们这边的问题，一个是对方明确说「现在不行」**。

**⚠️ 顺带改一句 067 期关于 `Hydrogen` 的话**：067 期写「`Antigravity` 里它只给付费 `AI Pro` / `Ultra`」（依据 `blog.google` 发布帖，那句是对的）。本期 `Antigravity` 自己的页面顶部横幅写「**Gemini 4 Hydrogen and Orchestrator now in Google Antigravity**」—— **两句都成立**：发布当天只给付费、后来进了产品、**页面上仍不写它在哪一档**。**本报不把「进了产品」升级成「免费档有了」**，也不把 067 期那句判成错。

## 六、避坑提示（本期补入 3 条：294–296）

**294 · `?search=` 不生效时，「搜不到」与「不存在」是两件事。** 本期在两个端点上都撞到这个坑：`openrouter.ai/api/v1/models?search=ling` 返回 **`471` 条（全量）**、`hf-mirror.com/api/models?search=Ling-3.2` 返回的 `13` 条全是无关仓库（`llama3.2-libllm`、`HuggingFace` 上的各种 `ling` 用户名），**参数被服务端忽略了而不是命中了空**。**065 期立的是「空数组只证明没有叫这个名字的东西」；本期补的是另一半：非空数组也可能只是「参数没被接受」。** 纪律：**凡用 `?search=` 得到「有」，一律再用「全量 + 本地 `in` 过滤」验一次**（本期 `Ling 3.2` 的结论就是全量过滤得出的：`471` 条里 `ling-3.2` 只有 `:free` 一条）。

**295 · 免费区 `+1` 只说明「列表 `+1`」—— 列表 / 端点 / 权重是三层，`hugging_face_id` 是预留位不是承诺。** `Ling 3.2 Flash` 三层全查：列表有（`:free`、零价）、`/endpoints` 是 `[]`、`hugging_face_id` 指向的 `inclusionAI/Ling-3.2-flash` 是 `404`。**`OpenRouter` 的模型 `JSON` 里那个 `hugging_face_id` 字段是厂方填的字符串，平台不校验仓库是否存在** —— 本报此前把它当成「权重在这」的证据用过，本期起改口径：**报「权重在哪」只认 `hf-mirror` 单仓端点 `200`**。

**296 · 字节变化可以完全由构建指纹造成 —— 先比可见文本，再比字节。** `MiniMax` 定价页 `331,542 → 311,690`（`−19,852`），两期可见文本**都是 `111,720` 字、逐字相同**，差异全在 `dist-*.js` 哈希与部署编号。**067 期写过「页面变小与说了新东西之间没有必然关系」，本期给出机制**：`Next.js` / `mintlify` 一类构建会把哈希与签名写进 `HTML`，一次重新部署就能让字节数上下浮动几万。**纪律：报「页面变了」之前，先做一次「剥 `script`+`style`+标签+零宽字符后逐字比较」，字数相同就写「只动了构建指纹」。**
