### 工程侧经验（本期四个新增，均已写进 `ENGINEERING.md`）

1. **`check_frozen.py`**：本期 🔴 0。**一次 🔴 是因为写了"本期无新增命中"**——
   `| **上海人工智能实验室（书生 / InternLM）** | … | 本期无**新增**命中（010 期…Intern-S2-397B GGUF）|`，
   `新增` 距关键词只有几字符。**改为「本期未命中（010 期曾取得实质进展，条目为 …）」后通过**。
   **再次印证：首见期早的泛品牌关键词旁边不要用 `新增`/🆕。**
2. **第四章状态列的文本会被 `extract_deadlines.py` 字面读入 → 归类错**：智谱那条要从"已结束"
   改回"生效中"，状态格写成 `🟢 生效中（状态反转：本行由"已结束"改回…）`，
   **那三个字被字面命中、整行又被归进【C】已结束**。**改法：叙述状态反转不要复述旧状态词**
   （写"本行由终止状态改回生效中"）。**同源**：`check_frozen` 的 25 字符窗口、
   `check_deadlines` 的关键词优先，**都是"按文本原义读"的守卫**。
3. **色标归一**：状态格**第一个字符必须是颜色**（`cells[2][0]`），部分行从状态文本里带来第二个
   emoji 导致取色取错。**先归一（每格首色对齐行首标记）→ 再跑计数脚本读 `cells[-1][0]` 复核**
   （本期 🔴 4 / 🟠 11 / 🟡 15 / 🟢 34 / ⚪ 11 = 75，与 `check_deadlines` 的 75 互证）。
4. **`git push` 凭据坑（本期新踩，必须记住）**：`credential.helper=helper-selector` **返回空**，
   `GIT_TERMINAL_PROMPT=0` 下立刻失败；换 `helper=manager` 会**卡在 GCM 交互回退上 2 分钟无输出**
   （沙箱内外一样）。**可用写法**：`git-credential-manager get` 直接取令牌（本身好用，
   `gho_` 40 位 / API 200），再喂给**内联助手**——
   `git -c credential.helper= -c credential.helper='!f() { echo username=Lavie-purple; echo "password=$GH_TOK"; }; f' push origin main`。
   **空值 `credential.helper=` 必须先清掉 helper-selector**；令牌只走环境变量、不落盘。
   另：`timeout` 在 Git Bash 会解析到 `C:\Windows\System32\TIMEOUT.EXE`，**要用 `/usr/bin/timeout`**。
5. **Pages 构建要等，抓一次会误判**：推送后 `pages/builds/latest` 先返回 `building`，
   **此时带 `?t=<ts>` 抓首页拿到的仍是上一期**（本期首次抓取显示「更新至 第 010 期」，
   线上 16,533 B vs 本地 16,879 B）。**顺序：push → API 核 sha → 轮询到 `built` → 再抓线上页**。
