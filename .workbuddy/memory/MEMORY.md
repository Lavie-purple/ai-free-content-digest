## 出刊约定

- 每期只做**增量 + 纠错**，不重复往期已固化内容（先跑 `check_frozen.py`，🔴 高危会 exit 1）。
- 结构固定十节：摘要（3 秒版）→ 一 AI 免费内容发布 → 二 免费内容生成工具 → 三 常驻免费额度与 API →
  四 限时活动与截止时间表 → 五 本期纠错清单 → 六 避坑提示（编号跨期连续）→ 七 按任务选型速查 →
  八 信源体系更新 → 九 来源与核查说明。**发布线与「免费内容」线是必备两章，不能省**。
- 交付前用脚本核对所有表格列数（`check_tables.py`），并检查避坑编号与前一期连续。
- **刊头必须标注扫描截止时点**。**工作日早间出刊必然漏掉当天上午晚些时候的发布**（009 期头条 Step 5 Preview 出现在 10:20）。
- **同日双刊**：刊头**必须显式声明**「XX 期是当天的正式刊、本期是同日第二轮（增补轮）」，写明
  「两期不合并、不互相覆盖」，**窗口起点 = 上一期扫描截止**，**必须写清美西 / 北京双向换算**；
  **「隔日出刊」要用完全不同的句式**，否则读者会把窗口算重。
  **先例**：001/002、003/004、026、030/031、032+033（10/12）。
- **短窗口触发纪律（026 期定）**：上期截止距今不足 2 小时时，**先核「窗口内是否确有落在线后的硬条目」再决定出刊还是挂账** ——
  **只看窗口长度会误判**。核验法：上期 md 全文检索该条目关键词（0 命中 = 上期未覆盖）+ 用聚合层时间戳把落地时刻锚到上期截止之后 N 分钟。
- **「计数」与「明细」必须同源生成**：凡出现数字，**要么全从表里算、要么全在正文里定义**；
  **禁用句式「状态变更共 N 处」**；**台账正文写「（N→M）」必须当场用表体行数验一遍**。
- **继承字段必须重算（027 期）**：凡含基准日语义的（距今 N 天 / 倒计时 / 第 N 天 / 剩余）必须在基准日变化后重算。
  ⚠️ **`extract_deadlines` 只解析「截止」列、不解析状态列里的倒计时文本，脚本守卫覆盖不到** ——
  复核办法是**逐行用「截止日 − 基准日」再算一遍**。⚠️ **正确断言是「每行天数 == 截止日 − 基准日」**，
  **不是「推进一天就 −1」** —— 继承误差会逐期滚雪球（040 期实测）。
- **非日期类计数也不得沿用上一期（029 期）**：站点计数器 / 目录家数 / 名单条数这类**流通量字段**定稿前**必须重取一次**，
  **且不得据旧值写趋势判断**。**「重取」的三种结果（升 / 降 / 同值）都要记账，「与上期同值」不得省略**。
- **上游撤掉某个计数口径时**：「沿用旧值 + 标注核对日 + 声明口径已变、两期不可相减」是正确收口，
  **不得为凑数而换一个不可比的新数字**（030 期 OpenRouter 目录页改版）。
- **「降档」必须一次写全三样（028 期）**：**模型 / 上下文 / 额度口径**各降到什么。
- **对已跟踪厂商按四条线分别过，不按「新闻条数」过（028 期）**：**模型线 / 额度线 / 产品线 / 政策线**；
  **「图像 / 视频模型线」与「内容平台榜单线」是固定扫描位**（Nano Banana 2.1 连漏三期的根因）。
- **「定编扫描位」当期就要写成「两维交叉关键词表」并当日实跑（030 期）**：例·决策模型线 = **输入模态 × 售卖形态**。
  **纪律停在文本层 = 没有纪律**。
- **「开放」一律拆四层写**：**能用吗（免费额度）/ 能下载吗（权重日期）/ 能跑吗（显存·集群）/ 能商用吗（许可证）**（避坑 41）。
- **涉及多站点口径的**（WorkBuddy 国内站 vs 国际站、混元新老平台）**必须显式拆开写**。
- **截止表标三态**（生效中 / 换挡日 / 已结束），优先复核「最近 3 天内的节点」。
  **第四章截止表一律由脚本生成、不再手抄**：每期新写 `gen_tableNNN.py` + `injectNNN.py`
  （提取上期表块 → 断言行数 → 套 `REWRITE` → 正则重算「距今 N 天」→ 新行插在 ⚪ 存档块之前 → 再断言总数），
  **md 里的 `<<<TABLE4>>>` 占位符必须为 0**（靠 `verify_web` 的「占位符 0」守卫）。
  ⚠️ **换挡日不能写可被解析的实日期**（036 期）—— 写带横线的 `2026-10-14` + 注明「非活动截止」。
- **第四章脚注固定四段并逐段打勾**：① 三态分布 ② A/B/C/D/E（`check_deadlines` 实跑）
  ②-补 **双口径三态**（色标口径 vs `classify()` 口径，**两套都写、逐条解释差值**）③ **逐行 diff + ⚠️ 下一轮强制动作**。
  两条固定口径：**⚪ 与 C 差 1 是正确口径**（`GitHub Models 免费层` 的 `2026-07-30` 非解析器认的 `M/D` 写法，归 D，勿修正）；
  **色标口径与 classify 口径可差 1–4 条**，**两套数字都写、正文一律以脚本口径为准**。
  ⚠️ **两套口径数字与「差值 N 处」必须从 `deadlines.csv` 实跑**（034 期）—— **差值 = 「色标为 🟠/🟢、`状态` 却是 `pending`」的行数**，**预写必错**。
- **同仓库两种行尾**：`data/` 下 CRLF、`memory/` 下 LF —— 混用会让 `git diff --stat` 显示成整文件重写。

## 内容口径纪律（按期次归档，样本见 ENGINEERING §十）

- **030 期**：「同类源分开记账」→ **同类源之间也要标口径**（032 期升级：同一批 `OpenRouter :free` 模型 `Inferse` 给 22、`freellm.net` 给 19，**两个数都要带来源读、不可互换**）。
- **031 期**：**有预告的续期窗口回扫到期条目必须读活动页正文**（避坑 140）—— ①**「无缝续期」≠「同一活动」**（额度量纲可能全变）
  ②**「活动收口」≠「已领的用完了」** ③**有预告的续期反而最容易拖**。
  **「开源」是时点状态**（避坑 139）：必写「核对于 YYYY-MM-DD」；**权重许可证与运行时代码许可证分开核**；商业闸门看门槛细则。
  **决策模型固定字段**（避坑 141）：**双分数（记「取的是哪个分」）+ 校准 ECE/Brier + 熟悉技能 vs 新领域落差**。
  **检测工具的「阴性结果」不是证据**：措辞写「**未检出支持的水印**」（避坑 138，与避坑 116 互为镜像）。
- **032 期**：**一个模型有五个日期**（公告日 / 文档出现日 / 权重上传日 / 可访问日 / 核对日）→ 避坑 142。
  **「开放权重」≠「有公告」**（避坑 143，名单第一来源是 HF 组织页与厂商 X）；**世界模型 / 具身榜单的「榜首」要连选法一起读**（避坑 144）；
  **别把 agent 编队当「加人」算成本**（避坑 145）；**「覆盖率声明」不是「准确率声明」**；
  **长期挂账要设「疑似实质违约候选」档**（ZCode 月报已连续多期未见）。
- **034 期**：台账加行时 `## T0 · 根节点（N）` 要按「所有被改动的子节」重算；**首页「信源 N 条」= 五个 `## T\d` 括号求和**。
- **036 期**：**「加行」与「加行加对节」是两件事** —— 改完跑 `.workbuddy/audit_src036.py` 逐节「括号数 vs 实际行数」核对（表内行 + 表外补登行都算）。
  **「手写计数」与 `build_source_hits` 实跑行数不是同一口径**（后者只认表内数据行，**两级口径不可相减**）。
- **037 期**：**「开放权重」必须连「下载闸门」和「许可类型」一起读**（避坑 162，五个必问：ungated？审核方式？有无 ungated 镜像？是不是 Apache？否则抄四条条款）。
  ⚠️ **「衍生作品」定义宽度最容易漏**（`Muse Model License` 把「用其输出训练/微调/蒸馏的模型」也算 → 小模型同样要署名；同期 `Ling-3.1-flash` 是 MIT、零义务）。
  **「某模型免费了」三问**（避坑 163，与 159 分工：**159 管哪个规格被砍，163 管免费的是哪一档、范围多大**）：
  ①免费的是哪一档 ②免费档能力是不是同一个 ③范围有多大。⚠️ **同一模型在同一平台可被免费两次而窗口不同 → 不要当成同一轮活动**。
  **平台停服与额度到期不是一个量级**（避坑 164）：见「X 日停止服务」立刻记**停服日 / 最后新建日 / 最后导出日 / 迁移目标**四样，
  硬后果写清三条（平台与 API 关闭、已分发渠道停止响应、后台控制台关闭）。与避坑 47/78 分工：**47 讲厂商不给日期，164 讲给了日期怎么排**。
  **看到「最强」要问三件事**（避坑 165）：**在哪个维度最强、按谁的表、是平均还是单项** —— ①找「本模型落后于谁」那一行 ②自报还是独立复现 ③限定词逐字读。
  与 116 分工：**116 管「这是谁说的」，165 管「同一张表里怎么读」**。
- **041 期**：**同一个 URL 的活动内容可以被官方就地改写，而 URL、发布日期、活动期都不变 → 引用活动规则必须现场打开**（避坑 179）：
  ①列表页标题与日期只够判断「有没有这条」，不够引用规则 ②**总量数字只能做规则表求和验算（验自洽），验不了新鲜** ③转述方的「错过了就 X」是强断言，要单独复核。
  **「连续 N 期未见」是待办状态、不是事实判断**（避坑 180）—— 处置：**按四条线分别过 + 挂账项直接访问厂商页面，不能只靠聚合层**。
  **地区限制常只挂在清单里的某一行上，「页面没写」≠「没有限制」**（避坑 181）——
  **「能免费用」与「能参赛 / 可获奖」是两个独立的地域资格**。
  **「免费 N 个月」是额度期限、不是申请期限**（避坑 182）—— **「没有申请截止日」≠「可以慢慢来」**；**审批类权益与领取类权益分开登记**。

## 042 期（2026-10-20）新增五条口径纪律

- **同 URL 被改写之后「错误转述」不会自己停下来，且复制品看起来完全正常**（避坑 183）：
  本期 `AutoClaw` 国际站**连续第 2 次实访仍是 85M（未被改回）**，而**10/20 当天新发布的一篇聚合稿仍按旧版写
  「今天起每天 500 万」并给出「整期 6000 万」—— 照它操作今天少领 2,500 万**。**三条机制**：官方改写不通知任何转述方；
  **旧版一旦被转述就成了可被继续引用的「既有事实」（本期这篇引的是另一篇更早的同错稿件，错误在二次传播中获得独立生命力）**；
  **错的数字往往算得对**（`30M+5M×6=60M` 完全正确，**错在依据的那张表已不是现行表**）。
  **在 179「现场打开」之外加一条更便宜的判据：核对「今天属于哪一档」**（本例只需看规则表第一行）。
- **跨组织事件处置里「谁承诺了什么」必须逐家抄**（避坑 184）：本期 `OpenCode` 事件**四家四种状态，
  只有 `OpenAI` 用了「承诺」**（`OpenCode` 是「正在进行/已启动」、`Anthropic` 与 `Google` 是「封禁」且本轮未核到退款承诺）。
  **动词就是口径，「承诺/正在进行/已启动/封禁」不可互换**；**「未核到某家承诺」要写「未核到」，不能写「该家不退款」**。
- **安全护栏会按场景拒绝防守方，这类通道必须提前申请**（避坑 185）：`OpenCode` 事件中攻击者连攻 48 小时，
  而**分析攻击代码的模型识别出恶意载荷后直接拒答**，直到拿到 `Daybreak Blue` 权限才恢复分析能力；
  **`Dax Raad` 明说「碰巧几天前提交、前一天才获批」**，而该项目有身份验证与硬件安全密钥等硬前置
  → **事后申请在流程上就注定来不及**（`Hugging Face` 7 月同一堵墙，非孤例）。
- **套餐的「模型名不变」可能是自动改路由**（避坑 186）：`MiniMax` 公告**自 10/19 起 `M Plan`/`Token Plan` 用户的
  `M2.5`/`M2.7` 请求自动改路由到 `M3.1 Flash Preview`**，而**旧模型名继续可用、套餐额度不变**
  → **你以为在测 M2.7、实际测的是 M3.1 Flash，而返回的模型名不会告诉你这件事，两档价格也不同**。
  **兼容层的承诺不覆盖路由层的事实**。
- **「试点期结束后改为 X」是条件式表述，条件里没有日期就不算日期**（避坑 187）：本期 `WorkBuddy` 教师计划写
  「2026 年 10–12 月为试点期，结束后改为混元 4 独享 1,600 + 其他 400」，**但未给试点期结束的确切日期**
  → **读者无法自己推算何时受影响**。**见到「试点期/灰度期/过渡期结束后改为 X」一律记三件：现状 / 变更后 / 生效时点是否确切**；
  第三件缺则状态写「生效时点未公布」，**不写任何具体日期**。
- ⚠️ **本期同时更正了 041 期的两处表述**（**多站点口径的反例样本**）：**「官方页上没有付费会员加赠」只对国际站成立**
  （国内站一手页明写付费会员每日 800 积分）；**「桌面端 2 亿一手页未核到」本期已核到，且国内站还有「每日 500/800」第二档**。
  **「多站点口径」三问**：**① 这条规则属于哪个站点（URL 主域名必须写进条目本身）② 另一个站点是否有独立规则页
  （本例两边 URL 路径相似但内容不同，只记路径不记域名必然混淆）③「没有这条规则」的结论是在哪个站点得到的**。
- ⚠️ **本期把「老模型下线」写成了本报告至今最鲜明的一组对照**：**`MiniMax` `M2.5/M2.7` 给了两个精确到日节点
  （10/19 新用户闸门、11/18 彻底退役且「请求不再工作」），而腾讯老混元连一个日期都不给（Q04 连续第 30 期）**
  → **避坑 47（厂商不发确切日期）与避坑 164（给了确切日期怎么排）是两条互补纪律，合起来才是完整的关停纪律**。

## 043 期（2026-10-21）新增五条口径纪律

- **「开放权重」是四个状态，不是一个状态**（避坑 188）：**① 宣布了模型（官方 API 可调）② 官方承诺会开权重
  （官方文字出现 `open-weight` 或 `weights will be released`）③ 给了具体日期（官方正文出现可解析日期）
  ④ 权重真的在 `HF` 上（组织页存在对应仓库）**。**核验顺序是 ①→②→③→④，缺哪一级就写「哪一级没到」**；
  **在 ④ 之前一律按「只能用 API、不能下载」规划**。⚠️ **同一家厂商的博客与文档站可以给出强度不同的承诺**
  （本期 `MiniMax`：文档站已标 `open-weight`、博客只写 `later`）→ **引用时必须说清是哪一处**；
  **第三方给的日期只能写成「第三方口径」** —— **写「官方确认 X 月 X 日开放权重」是失实的**。
- **开放权重的许可是五层，不是一层**（避坑 189）：**① 下载闸门 ② 许可类型 ③ 地域范围 ④ 商业门槛
  ⑤ 衍生义务**。**后三层最常被漏** —— **本期 `MiniMax-H3` 的许可把美/欧/英/韩明确列为 `Excluded Territories`、
  年营收超 `US$20,000,000` 需事先书面授权、并把「用其输出蒸馏的模型」也列为 `Model Derivatives`**。
  ⚠️ **必须同时给反例**（`MiniCPM-V 4.7` 是 `Apache-2.0` + `gated: false` + 无地域排除）——
  **否则读者会把「某家的模型有地域排除」误推成「这类的模型都有」**。
- **厂商自报的「防护提升了 X%」必须连分母、范围、有效期一起读**（避坑 190）：**① X 的分母是什么
  （本期 `Anthropic` 的 `90–99%` 是「数据采集量」，而页面摘要写的是「蒸馏发生率」——不是同一个量）
  ② 防护覆盖哪一段链路（自家 API vs 第三方托管）③ 官方有没有写有效期（`Anthropic` 自述
  「We don't yet know how long these gains will last.」）**。⚠️ **三句都能从原文抄到就照抄，抄不到就写「未公布」**；
  **且不写「防护失效」也不写「防护有效」**（避坑 116 / 132）。
