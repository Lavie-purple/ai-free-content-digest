## 出刊约定

- 每期只做**增量 + 纠错**，不重复往期已固化内容（先跑 `check_frozen.py`，🔴 高危会 exit 1）。
- 结构固定十节：摘要（3 秒版）→ 一 AI 免费内容发布 → 二 免费内容生成工具 → 三 常驻免费额度与 API →
  四 限时活动与截止时间表 → 五 本期纠错清单 → 六 避坑提示（编号跨期连续）→ 七 按任务选型速查 →
  八 信源体系更新 → 九 来源与核查说明。**发布线与「免费内容」线是必备两章，不能省**。
- 交付前用脚本核对所有表格列数，并检查避坑编号与前一期连续。
- **刊头必须标注扫描截止时点**。**工作日早间出刊必然漏掉当天上午晚些时候的发布**（009 期头条 Step 5 Preview 出现在 10:20）。
- **同日双刊**：同一天出两期时，刊头**必须显式声明**「XX 期是当天的正式刊、本期是同日第二轮（增补轮）」，并写明
  「两期不合并、不互相覆盖」；**窗口起点 = 上一期扫描截止**，且**必须写清美西 / 北京双向换算**。
  **「隔日出刊」要用完全不同的句式**，否则读者会把窗口算重。
  **先例**：001/002、003/004、026（凌晨增补轮）、030/031、**032（10/12 正式刊·跨日）+ 033（10/12 同日第二轮）**。
- **短窗口触发纪律（026 期定，改判留档）**：上期截止距今不足 2 小时时，**先核「窗口内是否确有落在线后的硬条目」
  再决定出刊还是挂账** —— **只看窗口长度会误判**。核验法：上期 md 全文检索该条目关键词（0 命中 = 上期未覆盖）
  + 用聚合层收录时间戳与厂商时区把落地时刻锚定到上期截止之后 N 分钟。
- **「计数」与「明细」必须同源生成**：凡出现数字，**要么全从表里算、要么全在正文里定义**；
  **禁用句式「状态变更共 N 处」**；**台账正文里凡写「（N→M）」增量表述，必须当场用表体行数验一遍**。
- **继承字段必须重算（027 期）**：从上一期抄来的字段，凡含基准日语义的（距今 N 天 / 倒计时 / 第 N 天 / 剩余）
  必须在基准日变化后重算。⚠️ **`extract_deadlines` 只解析「截止」列、不解析状态列里的倒计时文本，脚本守卫覆盖不到** ——
  复核办法是**逐行用「截止日 − 基准日」再算一遍**；暴露方式通常是摘要与表内对不上。
- **非日期类计数也不得沿用上一期（029 期）**：站点计数器 / 目录家数 / 名单条数这类**流通量字段**，定稿前**必须重取一次**，
  **且不得据旧值写趋势判断**。**「重取」的三种结果（升 / 降 / 同值）都要记账，「与上期同值」不得省略**
  （030 / 031 / 032 已连续三次同值，逐期记账）。
- **上游撤掉某个计数口径时**：「沿用旧值 + 标注核对日 + 声明口径已变、两期不可相减」是正确收口，
  **不得为凑数而换一个不可比的新数字**（030 期 OpenRouter 目录页改版）。
- **「降档」必须一次写全三样（028 期）**：**模型 / 上下文 / 额度口径**各降到什么 —— 缺一样，读者就判断不出谁受影响。
- **对已跟踪厂商按四条线分别过，不按「新闻条数」过（028 期）**：**模型线 / 额度线 / 产品线 / 政策线**。

- **「定编扫描位」当期就要写成「两维交叉关键词表」并当日实跑（030 期）**：例·决策模型线 = **输入模态（文本/图像/语音）

  **第四章截止表一律由脚本生成、不再手抄**：每期新写一份 `gen_tableNNN.py` + `injectNNN.py`

## 034 期（2026-10-13）新增三条口径纪律

- **「既有行内容更新 N 处」以 `REWRITE` 键数为准（脚本实跑），脚注不得手数**；**「新增行 / 行名有变 / 既有行改写」三层必须分开写** ——
  **行名里内嵌核对日的行（如 `OpenRouter 免费档（…本期重取于 YYYY-MM-DD）`）会在行名 diff 里显示成「改名」，它不是新条目**（避坑 150–153 之外的工程侧补充）。

- **台账加信源行时，`## T0 · 根节点（N）` 的数字要按「所有被改动的子节」重算** ——
  **只改 `### 模型与开源（N）` 而漏改 `### 政策与监管（N）` 会让 `T0（N）` 与子节求和差 1**；
  **`build_index_web` 首页「信源 N 条」= 五个 `## T\d …（N）` 求和**，**改完要做一次逐节行数自检**。
