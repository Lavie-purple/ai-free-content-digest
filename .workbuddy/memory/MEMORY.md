## 展示规则（用户明确定下的约定，2026-09-16）

- **`AI信息源分级清单-T0-T4.md` 不对外展示**。它是**内部信源管理台账**，只用于扫描时的路由与去重。
- 每次出刊**只 `present_files` 那一份日报**（`AI免费内容与权益速递-第NNN期-YYYY-MM-DD.md`）。
- 台账**照旧维护**（新增信源、缺口、能力说明都要就地更新），只是**不进展示列表**。
- **只有用户明确要求看台账时才展示它**——用户说「给我看信源清单」之类时才 present。

## 出刊约定

- 每期只做**增量 + 纠错**，不重复往期已固化内容（先跑 `check_frozen.py`，🔴 高危会 exit 1）。
- 结构固定：摘要（3 秒版）→ AI 免费内容发布 → 免费内容生成工具 → 常驻免费额度与 API → 限时活动与截止时间表 → 本期纠错清单 → 避坑提示（编号跨期连续）→ 按任务选型速查 → 信源体系更新 → 来源与核查说明。
- **发布线与「免费内容」线是必备两章，不能省**（用户提示词点名要求）。
- 交付前用脚本核对所有表格列数（逐行数 `|` 与分隔行比对），并检查避坑编号与前一期连续。
- 截止时间表要标 **生效中 / 换挡日 / 已结束** 三态，优先复核「最近 3 天内的节点」。
- 涉及多站点口径的（WorkBuddy 国内站 vs 国际站、混元新老平台），必须**显式拆开写**，不能合并成一句。

## 出刊流水线（顺序固定）

1. 读上期 md + `data/frozen_items.md` + `data/open_questions.md`
2. `check_frozen.py [src.md]`
3. `extract_deadlines.py [src.md]` → `check_deadlines.py [--days N]`
4. 写 md（增量 + 纠错）
5. `build_web.py` → `verify_web.py`（**必须 `VERDICT: ALL GREEN`**）
6. `build_source_hits.py` → `build_index.py` → `build_index_web.py` → `check_site_freshness.py`
   （**后两个每期必跑**，守卫须 ALL GREEN。008 期就是漏了 `build_index_web.py`，
   站点首页「更新至」卡在 007 一整天——`INDEX.md` 对了不代表线上首页也对了）
7. git commit + push，**调 GitHub API 比 sha 核实**，再**抓一次线上页面确认期号**
   （Pages 构建有 1–2 分钟延迟，响应 `max-age=600`；抓时带 `?t=<ts>` 绕缓存）
8. 写自动化记忆 + 当日日志

## 硬要求

- **每期执行完必须写记忆**（自动化 memory.md + `.workbuddy/memory/YYYY-MM-DD.md`）。003、004 期就是漏写后补的。
- **编号以「期号」为准**，不用「第 N 次触发」——两者会脱钩。
- **不做物理归档**：旧期不挪子目录（自动化要跨期回读防重复），用 `INDEX.md` 解决"找得到"。
- **禁止删除工作区文件**；整理只整合不删除（用户长期约定）。
