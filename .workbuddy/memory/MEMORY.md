## 展示规则（用户明确定下的约定，2026-09-16）

- **`AI信息源分级清单-T0-T4.md` 不对外展示**。它是**内部信源管理台账**，只用于扫描时的路由与去重。
- 每次出刊**只 `present_files` 那一份日报**（`AI免费内容与权益速递-第NNN期-YYYY-MM-DD.md`）。
- 台账**照旧维护**（新增信源、缺口、能力说明都要就地更新），只是**不进展示列表**。
- **只有用户明确要求看台账时才展示它**——用户说「给我看信源清单」之类时才 present。

## 出刊约定

- 每期只做**增量 + 纠错**，不重复往期已固化内容（先跑 `check_frozen.py`，🔴 高危会 exit 1）。
- 结构固定：摘要（3 秒版）→ AI 免费内容发布 → 免费内容生成工具 → 常驻免费额度与 API → 限时活动与截止时间表 → 本期纠错清单 → 避坑提示（编号跨期连续）→ 按任务选型速查 → 信源体系更新 → 来源与核查说明。
- **发布线与「免费内容」线是必备两章，不能省**（用户提示词点名要求）。
- 交付前用脚本核对所有表格列数（逐行数 `|` 与分隔行比对），并检查避坑编号与前一期连续。
- 截止时间表要标 **生效中 / 换挡日 / 已结束** 三态，优先复核「最近 3 天内的节点」。
- 涉及多站点口径的（WorkBuddy 国内站 vs 国际站、混元新老平台），必须**显式拆开写**，不能合并成一句。
- **刊头必须标注扫描截止时点**（避坑 40 / 010 期起固定栏目）。**工作日早间出刊必然漏掉当天上午晚些时候的发布**
  ——009 期头条 Step 5 Preview 出现在 10:20，若按 09:20 定稿会整个漏掉。
- **「开放」一律拆四层写**：**能用吗（有无免费额度）/ 能下载吗（权重日期）/ 能跑吗（显存·集群）/ 能商用吗（许可证）**
  （避坑 41，010 期）。厂商说「开源」时先问这四问，别把它压成一句「开源了/没开源」。
- **短窗口触发纪律（026 期定，改判留档）**：**上期扫描截止距今不足 2 小时时，先核「窗口内是否确有落在线后的硬条目」，再决定出刊还是挂账**——
  **只看窗口长度会误判**。核验方法：拿上期 md 全文检索该条目的关键词（026 期：`Startups` / `创业` / `Tech Week` 均 0 命中 = 上期确实未覆盖）
  + 用聚合层收录时间戳与厂商时区把落地时刻锚定到「上期截止之后 N 分钟」。**同日两期不是禁区**（001/002、003/004 已有先例），
  但**必须在刊头显式声明「这是增补轮、下一轮才是当天的正式刊」**。（026 期初判暂缓 → 找到硬增量后改判出刊，两次判断都留在自动化记忆里。）
- **「计数」与「明细」必须同源生成（026 期纠错教训）**：025 期刊头写「10/7 同日收口 4 项」，同文第四章表内却是 6 行同为 10/7 截止
  ——**一处手写、一处引表，读者按哪处都对不上**。**凡出现数字，要么全从表里算，要么全在正文里定义**（与避坑 120 同源）。
  **027 期同类再犯一次**：第九章写「状态变更共 10 处」，把「改状态」与「加新行」混进一个数字、且「新增 🟢」少算 6 条 →
  已改为**三组同源数字**（表体 98→109 行 / 新增 12 个行名（11 条全新 + 1 条改名）/ 既有行色标变化 7 处）。
  **禁用句式：「状态变更共 N 处」。**
- **继承字段必须重算（027 期自检教训）**：**从上一期表里抄过来的字段，凡含基准日语义的（「距今 N 天」「倒计时」「第 N 天」「剩余」）
  必须在基准日变化后重算**——027 期有 **16 行**原样沿用了 026 期的数值（基准日已 10/7 → 10/8，应全部 −1）。
  ⚠️ **`extract_deadlines` 只解析「截止」列，不解析「状态」列里的倒计时文本，脚本守卫覆盖不到这类错误**；
  暴露方式通常是**摘要与表内对不上**，复核办法是**逐行用「截止日 − 基准日」再算一遍**（027 期已写进第四章脚注与第九章）。
- **第四章截止表一律由脚本生成，不再手抄（027 期首落地 → 028 期定型）**：从上一期 md 提取表块 → **先断言行数**（028 期 `assert len(body) == 109`）
  → 按行名前缀套 `REWRITE` 字典 → **用正则重算每一行的「距今 N 天」** → **新行一律插在 ⚪ 存档块之前** → **再断言总数 `109 + len(NEW_ROWS) == 120`**。
  脚本：`.workbuddy/gen_table028.py`（每期新写一份）。**「手抄掉行」与「继承倒计时不重算」两类历史错误都由这一步根治。**
- **生成式写法必须配「占位符 0」守卫（028 期）**：md 里先写 `<<<TABLE4>>>` 占位、后由脚本注入表格 —— **交付前必须跑 `verify_web`**
  （它的「占位符 0」这条就是为这类残留设的；028 期确实是靠它才查出 md 里还留着占位符与两处正文错字）。
- **「降档」必须一次写全三样（028 期）**：凡写某免费档「收缩 / 只剩 X」，**必须同时写清 模型 / 上下文 / 额度口径 三样各降到什么**
  —— 027 期只写「Gemini 免费档只剩 Flash-Lite」，漏了「上下文降到 32K + 按算力消耗计量（每 5 小时刷新 + 周上限）+ low/medium/high effort 三档」，
  读者据此判断不出谁受影响。**纪律：凡写「降档」，必须同时写「哪三样一起降」。**
- **对已跟踪厂商按四条线分别过，不按「新闻条数」过（028 期）**：**模型线 / 额度线 / 产品线 / 政策线**。
  027 期只跟 Anthropic 的模型线，**漏掉同周整套 artifact 线（含「免费档扩容」这类关键变更）**。
  这是 024 期「版本线」、027 期「榜单线」之后的**第三次加固**；**「图像 / 视频模型线」与「内容平台榜单线」已并入固定扫描位**
  （028 期 Nano Banana 2.1 连漏三期的根因就是没有独立图像扫描位，已升格为避坑 129）。
- **第四章脚注必须先跑脚本再回填**，且要写全三段：**三态分布（`extract_deadlines` 口径）+ 到期巡检 A/B/C/D/E（`check_deadlines` 实跑）+
  相对上期的逐行 diff**。两条固定口径说明：① **⚪ 与 C 差 1 是正确口径**——`GitHub Models 免费层` 行 `2026-07-30` 不是解析器认的 `M/D` 写法，
  **归 D 不归 C，勿修正**；② **色标口径与 classify 口径可差 1 条**（如「🟢 未开始」行，脚本按「关键词优先于色标」归 pending），
  **两套口径都要在脚注里说清，正文一律以脚本口径为准**。

## 出刊流水线（顺序固定）

1. 读上期 md + `data/frozen_items.md` + `data/open_questions.md`
2. `check_frozen.py [src.md]`
3. `extract_deadlines.py [src.md]` → `check_deadlines.py [--days N]`
4. 写 md（增量 + 纠错）
5. `build_web.py` → `verify_web.py`（**必须 `VERDICT: ALL GREEN`**）
6. `build_source_hits.py` → `build_index.py` → `build_index_web.py` → `check_site_freshness.py`
   （**后两个每期必跑**，守卫须 ALL GREEN。008 期就是漏了 `build_index_web.py`，
   站点首页「更新至」卡在 007 一整天——`INDEX.md` 对了不代表线上首页也对了）
7. git commit + push，**调 GitHub API 比 sha 核实**，再**抓一次线上页面确认期号**
   （Pages 构建有 1–2 分钟延迟，响应 `max-age=600`；抓时带 `?t=<ts>` 绕缓存）
   - ⚠️ **push 若报 `could not read Username … terminal prompts disabled`**：本机
     `credential.helper=helper-selector` 是**坏的（返回空）**。用 `git-credential-manager get`
     取令牌 + **内联助手**推（`-c credential.helper=` 先清空 → `-c credential.helper='!f(){…}'`）；
     **别改用 `helper=manager`——会卡死在 GCM 的交互回退上，2 分钟无输出**（沙箱内外一样）。
     详见 `ENGINEERING.md` §九。（`timeout` 在 Git Bash 要写 `/usr/bin/timeout`。）
   - ⚠️ **抓线上页之前必须先轮询 `repos/<owner>/<repo>/pages/builds/latest` 到 `built`**——
     构建期间带 `?t=` 抓到的**仍然是上一期**（011 期据此误判过一次"没更新"）。
8. 写自动化记忆 + 当日日志

## 硬要求

- **每期执行完必须写记忆**（自动化 memory.md + `.workbuddy/memory/YYYY-MM-DD.md`）。003、004 期就是漏写后补的。
- **编号以「期号」为准**，不用「第 N 次触发」——两者会脱钩。
- **不做物理归档**：旧期不挪子目录（自动化要跨期回读防重复），用 `INDEX.md` 解决"找得到"。
- **禁止删除工作区文件**；整理只整合不删除（用户长期约定）。
- **改台账正文加信源行时，必须同步改清单章节标题里的手写计数**（`## T4 …（12）`、
  `### 政策与监管（15）`、顶部"T0 内部分类复核"那行）——`build_index_web.py` 首页的
  "信源 N 条"就是从这些括号数字求和来的，**只加行不改数，站点首页会显示旧数字**。
  加完用 `build_source_hits.py` 实跑的行数对一遍（009 期：98+19+18+36+14 = **185** ✓）。
- **`T0 内部分类复核（025 期）` 那一行的括注是历史基线标签，不要改名成当期期号**（026 期曾在正文里引用一个文件里不存在的
  「（026 期）」行）。**当期增量追加在该行尾部**，正文引用一律写成「`T0 内部分类复核` 汇总行」。
- **根目录命名雷区（2026-09-23 评审时发现）**：`build_index.py` / `build_index_web.py` /
  `check_site_freshness.py` 都以 `DEF = "AI免费内容与权益速递-"` 为前缀匹配。
  **凡根目录下以该前缀开头、且文件名含「第NNN期」的新 md，都会被当成一期日报收录，并可能顶掉首页"更新至"。**
  新增非日报文档（评审、规范、设计）→ 换前缀，或放进子目录。
  `check_site_freshness` 只覆盖"首页更新至 = 最新一期"，**不覆盖"最新一期内容是否完整"**。
- **本地存档不进公开仓库**：`对话记录.md`、`vibe-coding-评审报告-*.md` 已写入 `.gitignore`
  （仓库 `Lavie-purple/ai-free-content-digest` 是**公开**的）。要发布必须先让用户明确说。
