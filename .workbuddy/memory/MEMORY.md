## 展示规则
- **`AI信息源分级清单-T0-T4.md` 不对外展示**（内部台账，只用于路由与去重），照旧就地维护。
- 每次出刊**只 `present_files` 那一份日报**；**只有用户明确要求才展示台账**。
- **用户问「最简版 / 只看免费」时给 `quick.html`**（不是日报）：那条线只答四个字段。
- **三页是「一份刊物的三个视图」**：日报 / `quick.html` / `standing.html` 顶部同一位置都有三格切换器
  （极速 / 完整 / 总账，当前格实心 + `aria-current`），首页三格都不高亮。组件在 `viewswitch.py`
  —— **改一处、三页同时变**；**条数一律实算**。
- **「三页同构」由 `check_views.py` 守**（每期必跑）：三格齐全、当前格唯一、「完整日报」指向最新一期、
  格内条数与源文件实算一致；**任何一处不符 exit 1**。

## 出刊约定（全文见附卷 §十·22）
- **增量 + 纠错**，不重复往期已固化内容（先跑 `check_frozen.py`，🔴 高危 exit 1）。
- **十节固定结构**；**发布线与「免费内容」线是必备两章**。
- **刊头必标扫描截止时点**；**早间出刊必漏当天上午晚些时候的发布**。
- **同日双刊**：声明「正式刊 / 增补轮」+「两期不合并」+ 窗口起点 = 上期截止 + **美西/北京双向换算**；**隔日出刊换句式**。
- **短窗口（<2h）**：先核「窗口内确有落在线后的硬条目」再决定出刊/挂账。
- **「计数」与「明细」同源生成**；**禁用「状态变更共 N 处」**；台账写「（N→M）」当场用表体行数验。
- **继承字段必须重算**：断言是「每行天数 == 截止日 − 基准日」，**不是「推进一天就 −1」**。
  ⚠️ `extract_deadlines` **不解析状态列里的倒计时文本** → 必须逐行手算复核。
- **流通量字段不得沿用上期**，定稿前重取；**升/降/同值都要记账**；**口径变过不可相减**。
- **「降档」一次写全三样**（模型/上下文/额度）；**按四条线分别过**；**图像·视频模型线**与**内容平台榜单线**
  是固定扫描位；**「定编扫描位」当期写成两维关键词表并实跑**。
- **「开放」拆四层**（能用/能下载/能跑/能商用）；**多站点口径显式拆开写**（URL 主域名写进条目本身）。
- **第四章截止表一律脚本生成**（`gen_tableNNN.py` + `inject0NN.py`），**`<<<TABLE4>>>` 占位符必须为 0**。
- **第四章脚注固定四段**：① 三态分布 ② A/B/C/D/E 实跑 ②-补 双口径三态 ③ 逐行 diff + 强制动作；
  **⚪ 与 C 的差额不是常数** → **必须逐条归因**；**两套口径数字必须从 `deadlines.csv` 实跑**。
- **同仓库两种行尾**：`data/` CRLF、`memory/` LF。

## 050 期新增工程纪律（写脚本前必读）
- **① `prune_table.py --archive` 默认路径是相对路径** —— 在 `.workbuddy/` 下调用会写到 `.workbuddy/.workbuddy/data/`
  （**归档没进真档但表体已移出 = 事实丢失**）。**要么在仓库根调用，要么显式 `--archive "data/deadline_archive.md"`**。
- **② `split_ledger.py` 判「无截止日常驻档」靠截止列的**开头关键词**（`未公布`/`无结束日`/`无截止`/`未定`/`动态`/…）**，
  **不是语义判断** —— **写作格式是流水线的一部分，不是自由发挥**。
- **③ `gen_tableNNN.py` 的 REWRITE 键必须与源行文本**逐字符**一致**（写前先 `print` 源行原文）；
  **`NEW` 行末尾必须带 ` |`**。
- **④ 官方仓库图片可能是 git-LFS 指针** —— 真图走 `media.githubusercontent.com/media/…`。

## 052 期新增工程纪律（写脚本前必读 · 051 期漏改的根因都在这 · 全文见附卷 §十·20）
- **① ⚠️ 「脚本改写」必须断言它真的进了落盘文件** —— **051 期断言全过、10 行改写一行没进交付物**（写出循环判断写错一层 + 断言只校验字典不校验落盘文件）。
  **本期加三条断言**：**改写行数守恒 / 未改写行唯一 / 表体关键口径 == 正文关键口径**。
- **② ⚠️ 「注入源文件」必须与最终产物同步** —— **inject 源文件里存的是旧表格 → inject 一跑就把 `gen_table` 的改写覆盖回去**。
  **本期做法：`gen_table` 的输入直接取上期 md 的现行文本**。
- **③ ⚠️ `slim_table.py` 从不清理历史指针** —— **多期累积把行撑到 212–229 字**；**修法：瘦身前先剥掉历史指针（两种形态）**。
- **④ ⚠️ `slim` 的字数口径必须与 `lint` 的 R1 判据逐字一致** —— **不可多剔 `**`**（lint 不剔）。
- **⑤ ⚠️ 硬裁的预算要给「加粗标记 + 指针」留余量** —— **硬裁预算 = maxc − 16**；**且早退前也要复量落盘后长度**。
- **⑥ `gen_table` 的 `build()` 必须幂等** —— **split_ledger 已把改写写回总账 → 下一轮会二次改写**。
- **⑦ `inject` 必须注入「4.1 + 4.2 合并表」** —— **split_ledger 取「最长的一块表格」；分成两张表会让 4.2 变 0 行**。
- **⑧ `403` 的归因要先排除请求头** —— **`SEC EDGAR` 换合规 UA 即 `200`**（避坑 232）。
- **⑨ 短窗口（<2h）出刊判据** —— **先核「窗口内确有硬条目」再决定出刊/挂账**；**销项是增量，但不得把窗口外的销项包装成「窗口内新增」**。
