  **排查手法**：`faulthandler.dump_traceback_later(20, exit=True)` 会把栈停在 `build_web.py` 的 `re.match` 那一行，一眼定位。**已加防御**：段落分支在 `buf` 为空时改为"把该行当段落输出 + 强制 `i += 1`"——从此宁可渲染成朴素文本也不静默挂死；**改动后产物逐字节不变（已验证）**。

### 站点发布：两个「每期必跑」项（2026-09-19 事故，008 期）

- **症状**：`https://lavie-purple.github.io/ai-free-content-digest/` 在 008 期出刊后仍显示「更新至 **第 007 期**」，最新一期大卡片是 9/18 那期。而 `INDEX.md` 里 008 是好的——**两个产物一个跟上了、一个没跟上**。
- **根因**：出刊只跑了 `build_index.py`，**漏跑 `build_index_web.py`**。`index.html` 的 mtime 停在 9/18 09:11，比 008 期的 md 早整一天。**不是脚本坏了，是触发条件写错了**——工具表原先写「改首页后」，可每新增一期都等于改了首页，这句措辞本身就在鼓励漏跑。
- **为什么靠肉眼发现不了**：`git status` 是干净的（旧 `index.html` 早已随 007 期提交），`git push` 也成功、无任何报错。**只有把线上页面抓回来比对期号才会暴露**。
- **现在怎么防**：① `build_index.py` 与 `build_index_web.py` 的触发条件统一改成「**每期必跑**」；② 新增 `check_site_freshness.py` 守卫，落后即 `exit 1`（已用反向证伪验证：把 `index.html` 换成 007 版，精确报出 3 项落后）；③ `run_all.py` 默认任务已含 index / indexmd / fresh。
- **推 Pages 的完整收口顺序**：`build_source_hits.py` → `build_index.py` → `build_index_web.py` → `check_site_freshness.py`（须 ALL GREEN）→ commit → push → **API 核 sha** → **抓一次线上页面确认期号**。
- **CDN 缓存别误判**：Pages 响应带 `Cache-Control: max-age=600`。构建完成前抓页面会拿到旧副本（`X-Cache: MISS` 但内容是旧的，因为构建还没跑完）。自查时带随机参数（`?t=<ts>`）绕过本地缓存，并记住 **push 到构建完成有约 1–2 分钟延迟**，别把"还没构建完"误读成"没推上去"。查构建状态用 `GET /repos/{owner}/{repo}/pages/builds/latest`。

## 三、移动端适配（2026-09-17 定稿）

- **Windows 上 `--window-size` 量不了窄视口**：Edge/Chrome 最小窗口宽约 **490px**，320/375/414 全被静默夹到 489px。`--force-device-scale-factor` 只改 `devicePixelRatio`。**唯一可行路径是用 iframe 模拟宽度**（媒体查询按 iframe 宽求值），子页 `postMessage` → 父页写 `document.title` → `--dump-dom` 抓回。这就是 `probe_mobile.py` 的存在理由。
- **三档表处理策略**：2 列 → 纵向堆叠卡片（`thead{display:none}`）；3 列及以上 → 横向滚动 + `td{position:sticky;left:0}` 首列吸附；**截止表（台账）→ 卡片**，因为最关键的一列（截止日期）正好落在横滑视口之外，横滑等于藏起最重要信息。
- **`.tbl{overflow:hidden}` 会静默废掉 `td` 的 sticky**：表格自己成了滚动容器，sticky 参照它而非外层滚动器。CSS 不报错、看截图才发现首列跟着滚走。手机端块里必须 `.tbl{overflow:visible;border-radius:0}`。**验证法**：`wrap.scrollLeft=120` 后重量 `td` 的 `left`，不变才算粘住。
- **搜索框窄屏改「图标 → 展开全宽条」**：常驻会被压到只剩 26px 可用文本。输入框字号 **必须 ≥16px**，否则 iOS Safari 自动放大整页。
- **台账卡片列宽用 `grid-template-columns:max-content minmax(0,1fr)`**，不能用 `1fr auto`——长状态文字会把日期列挤成逐字换行。
- **触控目标 ≥40px**；`viewport-fit=cover` + `env(safe-area-inset-*)`（不支持的浏览器整条丢弃该声明，自动回退，无需 `@supports`）。
- **头部高度别写魔法数字**：JS `syncMetrics()` 从活的 `offsetHeight` 写 `--tb-h`/`--chips-h`，load/resize/`fonts.ready` 三处调用。
- 中文孤字/拆字：`text-wrap:pretty` / `text-wrap:balance`，或直接插 **WORD JOINER `&#8288;`**。
- 判定线：`verify_web.py` 仍须 `ALL GREEN`；`probe_mobile.py` 在 320/360/375/414 四档**横向溢出必须为 0**、触控偏小为 0、首列 `[粘住]`。

## 四、UI 审查的量化口径（2026-09-17 建立）

- **看截图不可靠，一律量 DOM。** 无头浏览器把指标写进 `document.title`，再用 `--dump-dom` 抓回来。实测抓到过两个只看截图会漏的问题。
- **「首列过窄」判据**（`probe_layout.py` 已内置）：实宽 < 140px **+ 行高 > 130px** + 首列 ≥4 字真文字 **+ 满足度 < 90%**，四条同时成立。行高门槛别调低（94px 只是正常折 2~3 行，会误报）；最后一条是为了不把「已按内容撑满」的列也标红。需求宽度用「临时 `white-space:nowrap` 后量 `scrollWidth`」得到。
- **量「压字」必须量文字矩形**：`h1`/`.pubnote` 是块级元素占满整行，量 `getBoundingClientRect()` 会稳定误报（右侧留白也算重叠）。改用 `TreeWalker` 遍历文本节点 + `Range.getClientRects()` 取每行矩形再求交。`mh-num` 定稿后与四块文字的矩形交集为 0。
- **截图三条硬规矩**（`probe_layout.py` 里已内置第一条）：① 必须先关入场动画 —— 页面大量用 `animation:...both` 起始 `opacity:0`，无头下会冻结在 t=0，拍出来「标题+正文整块空白」；② 想看中段**不能用「删兄弟节点」** —— 删掉 `.rail` 后 `.drawerwrap` 会掉进第 1 栏（196px），页面被挤成窄缝（实测 PNG 只有 15KB）；正确做法是保留栅格、只把前置内容 `display:none`；③ 一图一个 `--user-data-dir`，截完 `md5sum` 验一遍（全同=抓拍失败），再删 profile（每个十几 MB）。
- **配色审计看三样**：语义色色距（阈值 40；**同族色不互检** —— `accent` 与 `accent-ink` 本就该相近，放进 `SEM` 只会稳定误报）、WCAG 对比度（小字要 4.5）、整行 opacity 叠加后的实际对比度（脚本从源码正则读 opacity，**别写死**）。

**布局**

### 台账两个静默陷阱（2026-09-18 实测，各中一次）

- **`frozen_items.md` 的「首见期」列只能放期号，别加注解（025 期实测，已修脚本）**：`check_frozen.py` 用 `first == no` 判断"本期首登"。025 期给 `Intern-S2-397B` 写了 `025（存疑）`（意图是标注"发布日存疑"），**全等判断失败 → 该条被当成"往期条目"进入关键词扫描**；又因避坑 120 那行**结尾 16 字符内**出现「本期新增」而命中本为**表格行**设计的 `cond_b`，**误报 1 条 🔴 高危**（实为首登）。**已修**：`first_no = re.match(r"^(\d{3})", first)` 只取期号比对，注解既不参与判定、也不掩盖真重复。**教训不变**：`cond_a`（关键词前 25 字符）/ `cond_b`（行尾 16 字符）都对"「新增」+ 旧关键词"极敏感——**行文里一律用「本期登记 / 本期补入信源」替代「新增」**。

- **`check_frozen.py` 会误报"本期新增"**：写「**006 期新增。**」这类**标注往期**的话，若同一行后文出现某个已固化条目的关键词，那句"新增"就落进**关键词前 25 字符窗口**，被判 🔴 高危（007 期 `Union Alpha` 中招一次）。**改法：标注写成「006 期登记」**，或把关键词挪出窗口。
- **🆕 25 字符窗口的完整口径（009 期实测，一次出刊被它挡了 7 行）**：`cond_a = NEW_PAT in l[pos-25:pos]`，其中 `pos = 该行第一次出现关键词的位置`。**三个容易踩的形态**：
  1. **同一表格行跨越单元格**——`| 🆕 **做决策类…** | **TypeSafe AI Jev** |`：`🆕` 在第一个单元格，关键词在第二个单元格，**窗口照样命中**（`| **` 只有 4 字符）。**表格行不能靠"标记放别列"绕开。**
  2. **标题里的固定前缀**——`### 2. 🆕 可灵「看见微光」…`，即使改为 `🆕 快手公益 × 可灵`，`🆕` 距关键词仍只有 9 字符。**唯一稳的写法是把标记移到关键词之后 ≥25 字符处，或整行不用 `🆕`/`新增` 字样**（用「本期登记」「多了一个免费入口」等替代）。

- **沙箱会丢弃 `.git/refs/remotes/` 的写入**，所以 `git status` 常年显示 `[gone]`——**这是假象，别据此判断没推上去**。核实远端只能调 GitHub API 比对 `repos/<owner>/<repo>/commits/main` 的 sha 与本地 `HEAD`（`git push` 的回显也不可信）。
- **推销路：凭据助手取不到凭据时 `git push` 会直接失败或挂死（011 期实测，必须记住）**。本机 `credential.helper=helper-selector`（来自 `PortableGit/versions/1.2.0/etc/gitconfig`），但它**返回空**；在 `GIT_TERMINAL_PROMPT=0` 下立刻报 `could not read Username for 'https://github.com': terminal prompts disabled`。换成 `-c credential.helper=manager` 更糟——**卡在 GCM 的交互回退上，沙箱内外都不返回，2 分多钟无输出**。**可用写法**（命令行一条搞定，令牌不落盘）：
  ```sh
  export GH_TOK="$(printf 'protocol=https\nhost=github.com\n\n' | git-credential-manager get 2>/dev/null | sed -n 's/^password=//p' | tr -d '\r\n')"
  git -c credential.helper= -c credential.helper='!f() { echo username=Lavie-purple; echo "password=$GH_TOK"; }; f' push origin main
  ```
  **四个要点**：① `-c credential.helper=`（**空值**）必须显式写上，先把 `helper-selector` 清空，否则它仍会被调用；② `git-credential-manager get` 本身是好用的（011 期返回 `gho_` 40 位令牌，`api.github.com/user` → 200），**只有通过 git 调用它才出问题**；③ 令牌只走环境变量、命令里写的是 `$GH_TOK` 字面量，**不进 ps 列表、不落盘**；④ **`export` 不能漏（023 期实测）**——`"password=$GH_TOK"` 是**字面量**，由 git 派生的 sh 展开，只认**已导出**的环境变量。漏 `export` 时展开为空串，GitHub 回报
  `remote: Invalid username or token. Password authentication is not supported for Git operations.`
  **这条报错极容易被误读成"令牌过期"**，实际令牌是好的。**判据：`curl -s -H "Authorization: Bearer $GH_TOK" https://api.github.com/user` 返回 200（能看到 `login`）而 push 仍报 invalid token ⇒ 100% 是变量没 export（或要点 ① 那半句漏写），不是凭据问题**，别去重新取令牌、更别去动 GCM 配置。

### 033 期第 4 条（发布归档时发现 · 行尾 / EOL）

- ⚠️ **`.workbuddy/memory/` 下的 md 全部是 LF；追加内容时必须用二进制模式写，否则整个文件变 CRLF**：
  033 期归档时用了会在 Windows 下做 `\n → \r\n` 转换的追加方式，后果分三种 ——
  · `ENGINEERING.md` 278 → 295 行 **全部**变 CRLF；
  · `automations/<id>/memory.md` 1073 → 1108 行 **全部**变 CRLF；
  · `2026-10-12.md` 只有新增的 43 行是 CRLF（**混合行尾**，最难看出来）。
  **症状**：`git diff --stat` 显示 **1446 插入 / 1351 删除（≈ 全文件重写）**，而真实新增只有 **95 行** —— **相差近 30 倍**。
  **「一次记忆归档 commit 显示几千行变化」就是这个原因，不要误判成内容被重写或历史丢失。**
- **诊断一行命令**：`git diff --ignore-cr-at-eol --stat` —— 若数字骤降到几十行，即为**纯行尾差异**。
  **不要用 `grep -c $'\r'` 判断行尾**：Git Bash 下 `$'\r'` 被当成空模式，**结果恒等于总行数**（033 期据此误判过一轮）。
  正确做法是用 Python：`open(f,'rb').read().count(13)`。
- **修法**：`raw = open(f,'rb').read(); open(f,'wb').write(raw.replace(b'\r\n', b'\n'))`。
  **本仓库 `.gitattributes` 不存在、`core.autocrlf=false`** → git 不会自动归一，**只能靠自己**。
  **今后纪律：追加记忆前先断言 `raw.count(13) == 0`，追加后再断言一次。**

### §十·18 · 042 期（2026-10-20）五条实测样本

**① 「逐行 diff」这段诊断代码在 040 / 041 两期一直是死的 —— 它遍历的是已重算后的新值。**
041 期脚本（照抄 040 期写法）的结构是：先 `out = [recompute(l) ... for l in out]` **就地覆盖**，
**然后再遍历 `out`** 去比较「值 vs 真值」。**但那时 `out` 里已经全是重算后的新值了，拿它和真值比永远相等 → `diff` 恒为空。**
**后果**：**第四章脚注第③段要求的「逐行 diff」这一项证据，040 与 041 两期从来没有真正输出过任何一行** ——
它看起来在做对账、实则是恒真的死代码。**`assert not bad` 一直是有效的**（它跑在覆盖之前），
**所以两期的天数并没有算错，只是「逐行 diff」这项留痕是空的。**
**正确写法（042 期已修）**：**先 `before_snapshot = list(out)` 留快照 → 再覆盖 → 然后 `zip(before_snapshot, out)` 拿 before 与真值比。**
**修掉之后 042 期立刻输出了真实的 17 行 diff**（每行恰好 −1，因为 041 期的值本身正确）。
**教训**：**一段「对账 / 诊断」代码要先问「我比较的两个东西是不是同一份数据的两个时点」** —— 拿结果和自己比，等于没比。

**② `REWRITE` 的 `hits` 断言查错了对象，会假报「键没命中」。**
041 期写法是在**替换后的 `out`** 上数 `hits == 1`。**一旦新行名不再包含键子串**（042 期改行名时就发生了），
**`hits` 变成 0，断言报「键没命中」，但其实键在源表里好好地命中了一行** —— **报错信息指向错误的成因，会把人带偏。**
**正确口径（042 期起）**：**键必须在源表 `body` 里恰好命中 1 行；值必须出现在 `out` 里恰好 1 行。两件事分开断言。**
**附带一条**：**改行名时尽量保留键子串** —— 否则「行名 diff」会把「改写」误显示成「新增 + 删除」，
**而 034 期立的「新增行 / 行名有变 / 既有行改写」三层必须分开写这条纪律，全靠这个区分**。

**③ 台账加行脚本用「遇到某标题就插一行」当插入点，会把多行插进同一个小节。**

**根因**：**把「插入点」当成了「唯一定位」，而插入点必须由「所属小节的末尾」决定。**
**正确做法**：**先算出每个小节的行区间 `[start, end)`，再把行插到该区间最后一个非空行之后；

**核验顺序是 ①→②→③→④，缺哪一级就写「哪一级没到」**；**在 ④ 之前一律按「只能用 API、不能下载」规划**。

**② 避坑 189 · 开放权重的许可是五层，不是一层。**
**① 下载闸门 ② 许可类型 ③ 地域范围 ④ 商业门槛 ⑤ 衍生义务**。**后三层最常被漏** ——

⚠️ **必须同时给反例**（`MiniCPM-V 4.7` 是 `Apache-2.0` + `gated: false` + 无地域排除）——
**否则读者会把「某家的模型有地域排除」误推成「这类的模型都有」**。

**③ 避坑 190 · 厂商自报的「防护提升了 X%」必须连分母、范围、有效期一起读。**

## 《免费速查》quick.html（047 期结构改造 · 第三件产物）

### 为什么单独做一页
用户 2026-10-27：「主网页内容还是太臃肿……重点无非是：什么时候有免费、免费什么时候结束（还是定额常驻）、
免费的内容是什么、有多少量，这些才是最根本的。」

前面两轮（prune 砍条目、split 拆章节）治的都是**同一批数据的排列方式**，没治「读者要答的问题」。
日报的结构是「按信息类型分章」（发布 / 免费 / 工具 / 权益），而读者的第一个问题是「我现在能白拿什么」——
这两个顺序不一样，所以再精简日报也只是让错的顺序短一点。

### 只收什么
`deadlines.csv` 185 条里，**只有 61 条是「能拿到免费东西」**。另外 124 条的构成：
发布/开源 59、申报/活动 7、运维/停服 2、其他 49（榜单、评测、监管）。
**这些一律不进速查页**，并在页面顶部写明边界 + 给出完整版链接 ——
不写清楚，读者会以为漏了；写清楚了，这页就只是一页速查，不是残缺的日报。

### 数据从哪来：手工 CSV，不是正则抽
`.workbuddy/data/quick_items.csv`，7 列：`分组,名称,量,截止日,截止说明,状态,门槛`。
**必须手工维护**，原因：`deadlines.csv` 里「有多少量」这个字段根本不存在 ——
实测活动名里带数量词的只有 9%（16/185），从状态原文抽出来的是「一次」「一个」「两个」这类噪音。
所以 61 条的量是逐条从状态原文读出来填的，填不了写「未公布」，不估算。

### 每期怎么不失联：`--check`
`build_quick.py --check` 拿 `deadlines.csv` 里所有额度类条目，逐条与速查表算 **2-gram 集合的 Jaccard 相似度**，
低于 0.26 报「漏登」。同时 `SKIP_RE` 显式排除 9 条**故意不收**的
（无免费层 / 促销价 / 免费档改版 / 留存口径 / 地区限制 / 广告测试 / 停服 / 申报指南 / 清单类）。
实测：原始子串匹配误报 23 条 → 改相似度后 9 条 → 补 2 条真漏 + 阈值调到 0.26 后 **0 条**。
**阈值不能一味降**：降到 0.20 时「阶跃 Step 5 渠道免费周」和「Step 5 新用户套餐」会被判成同一条。

### 分区按「还剩几天」，不按章节
- **正在倒计时**：有确切截止日的（含 pending），按 `days` 升序；`crit` ≤0 天、`soon` ≤7 天、其余 `live`。
- **长期有效**：无截止日，按 6 个类型分组（Token 与积分 / 模型 API / 云资源 / 算力券 / 学生教育 / 开源）。
- **已结束**：`<details>` 默认折叠，做对照用。

### 三个实踩的坑
1. **`%` 格式化与 CSS 百分号冲突**。模板里 `width:32%}` 被 Python 当成格式说明符 →
   `ValueError: unsupported format character '}'`。改用 `string.Template` 的 `${name}`，CSS 里的 `%` 就不受影响。
   （注意：`Template.substitute` 遇缺失键会报错，`safe_substitute` 不会 —— 用前者，让漏传当场炸。）
2. **Chrome headless 有最小窗口宽度**。`--window-size=390,340` 实测 `vw=512`，
   截图只是把 512 宽的页面裁到 390 —— 会误判成「第三列被裁掉」。
   正确的移动端验证方式是**用 iframe 把页面套在 390px 容器里**再截图（`.workbuddy/tmp_mobile.html`）。
   这个坑差点让我去改本来没问题的 CSS。
3. **`display:contents` 才是移动端重排的关键**。窄屏要把三列表格变成「名称+日期 / 额度 / 门槛」三行，
   但门槛 `.need` 是嵌在 `.c-name` 的 td 里的 —— 给 td 设 `display:contents` 让子元素直接参与外层 grid，
   才能排出正确顺序；否则门槛会夹在名称和额度中间。

## 三页视图切换器 `viewswitch.py`（048 期后 · 2026-10-27 晚）

### 起因：三个页面是三个孤岛
用户 2026-10-27：「standing / quick / 日报 这三个都是零散独立开来的，想把 quick 作为极速视角挂在日报上，
总账按需打开。」实测比描述的更糟：
- `quick.html` 与 `standing.html` 里**一个回链都没有**（进去就出不来）；
- `quick.html` 边界说明里的「完整版日报」**错指到 `index.html`** —— 那是首页，不是日报；
- `standing.html` 因为是复用日报模板、期号正则匹配不到，页头写成了 **`#001` + 「第 001 期」**，
  而背景还有个大字水印 `001`。读者会以为这是创刊号；
- 日报页头只有一条指向 quick 的横幅，回头看不到总账。

### 设计取舍（几条是踩过才定的）
1. **三格顺序 = 阅读动线**，不按字母也不按文件大小：极速（现在能拿什么）→ 完整（本期变了什么）→
   总账（长期还给不给）。顺序本身就是给读者的建议路径。
2. **当前页用 `<span>` 不用 `<a>`**：点了没反应的链接会让人以为坏了。配 `aria-current="page"`，
   读屏软件同样知道位置。
3. **首页三格都不高亮**（`render(None, ...)`）：首页是目录，不是三个视图中的任何一个。
4. **条数一律实算**（读 `quick_items.csv` 与总账表格行），**不手写** —— 手写的数字过一期就是错的。
5. **副标题里的期号从 `full_href` 反解**，调用方不用各算一遍。少一处手写，少一处过期。

### 五个实踩的坑
1. **`latest_issue_html` 必须按文件名期号排序，不能用 mtime**。重建往期（补样式、改错字）会把 mtime
   刷新，用 mtime 会把旧期顶到最前，「完整日报」就跳到两个月前。
2. **总账不是「一期」**。`build_web.py` 原有 `issue = m.group(1) if m else "001"` 的 fallback，
   总账 md 标题里没有期号 → 落到 `001`。改成 `is_ledger` 三分支：
   `issue_line` / `issue_badge` / `mh_num`（背景大字水印要留空，否则「001」一直挂在那儿）。
3. **分隔符要跟着内容走**。模板原本写死 `__DATELINE__ · <em>增量与纠错口径</em>`，
   总账没有日期行 → 右上角孤零零挂一个「·」。改成整块 `__DATEBLOCK__` 由 python 生成。
4. **`quick.html` 是独立样式表**，只有 `:root` 那批颜色变量与日报同名，**没有 `--s4` / `--fast`**。
   所以 `viewswitch.CSS` 只用颜色与边框变量，间距写死 px；否则日报页正常、速查页失效。
5. **强调色用整行会反噬**。第一版给「极速视图」整行上了 accent 红，结果比当前页的实心块还抢眼，
   读者会以为它才是当前页。改成**只给图标上色**（`.vs-quick .vs-k i`）。

### 首页顺手修的两处
- **裸 Markdown**：首页头条与历史列表直接把 md 标题行搬过来，`**粗体**` 与 `` `反引号` `` 原样输出
  （048 期实测：大卡片 10 个 `**`、全页 152 个反引号）。加 `mdstrip()`：先去 `[文字](链接)` 留文字，
  再去 `** __ ~~ \``。**只去标记、不改字**。
- **两个文字段落 → 一排入口**：原来「免费速查」「常驻权益总账」各占一个 section、各写一段说明，
  与切换器信息重复。收成一排三格 + 一句说明。

### 移动端
640px 以下**不要三行堆叠**：日报页顶部已有固定导航条 + 刊头 + 说明框，再来三行切换器会把首屏占满。
压成**单行三格、隐藏副标题**（`.vs{grid-template-columns:repeat(3,1fr)}` + `.vs-d{display:none}`），
高度约 40px，390px 宽下三个标签都不折行。

#### 第二层根因：写出循环的判断写错一层


**修法（052 期落地，三条断言全加）**：

```python

for k in body:

        out.append(REWRITE[hit])
    else:
        out.append(k)
assert len(rewritten) == len(REWRITE)          # ① 改写行数守恒
```

#### 051 期的第二条漏改：REWRITE 键不够长

**`Runware` 分发层 `Kling 4.0` 促销行**与**快手可灵 `Kling 4.0` 模型行**的活动名都含 `Kling 4.0` ——

#### 052 期顺带修掉的六个脚本坑（全部实测）

1. **`slim_table.py` 从不清理历史指针** —— 049–051 期是「在状态列后**追加** `〔附录 NNN〕`」，
   **但不清上一期遗留的 `[附录 NNN](details.html)`**。052 期表体出现
   `[附录 049] [附录 050] [附录 051] 〔附录 052〕 〔附录 052〕` 这种五连指针，
   **把行撑到 212–229 字、直接触发 lint R1 超限（12 处）**。
   **修法**：`slim_status()` 开头先 `strip_pointers()` —— **两种形态都要剥**（md 形态与纯文本形态），
   剥完再追加本期指针。
2. **`slim` 的字数口径必须与 `lint` 的 R1 判据逐字一致** —— `lint_table.py` 的 R1 是
   「状态列**剔除 markdown 链接**后的字数」（**不剔 `**`**）；`slim` 的 `visible_len` 原本只去空白、不去链接
   → **slim 以为裁到位、lint 判超限**。**修法**：`visible_len` 也剔 markdown 链接。
   **⚠️ 不可多剔 `**`** —— lint 不剔，多剔会过度裁剪。
3. **硬裁的预算要给「加粗标记 + 指针」留余量** —— 硬裁发生在**加粗之前**（量的是 `visible_len(out)`），
   而落盘时会发生两件事：**① 整句被包进 `**…**`（多 4 字符）② 追加 `〔附录 NNN〕`（多 8 字符）**。
   **实测样本**：剥指针后 190 字（< 200，看似达标）、落盘后 202 字 → **R1 命中**。
   **修法**：**硬裁预算 = maxc − 16**；**且「未丢句子就早退」的判断（`if not dropped and new_status == status`）
   也要复量落盘后长度**（`visible_len(probe) + PTR_LEN <= maxc`）。
4. **`gen_table` 的 `build()` 必须幂等** —— 反复跑流水线时 `split_ledger.py` 已把改写写回《常驻权益总账》，
   下一轮 `gen_table` 再拿它当输入就会**对已改写的文本再改写一次**。
   **修法**：若该行已含本期标记（`（0NN 期）`）且待替换片段均不在，则**原样返回**。
5. **`inject` 必须注入「4.1 + 4.2 合并表」** —— `split_ledger.py` 取「第四章里**最长的一块表格**」当表体，
   再按截止列拆成 4.1 / 4.2。**若在 inject 阶段就分成两张表，它会挑错块 → 4.2 变 0 行**（052 期实测踩到）。
   **修法**：inject 注入**一个合并表**（4.1 行 + 4.2 行顺序混排均可），让 `split_ledger` 自行分流。
6. **`403` 的归因要先排除请求头** —— **本报告连续多期把 `SEC EDGAR` 的 `403` 记成「站点拒绝访问」**，
   实际是 `User-Agent` 不合规；**换成带联系方式的合规 UA（`AI-Free-Content-Report research@example.com`）
   后同一 URL 返回 `200`**（此前响应页标题逐字 `SEC.gov | Your Request Originates from an Undeclared Automated Tool`）。
   **归因错了，后续每一期都会重复记「未核到」**（新立避坑 232）。

#### 052 期的短窗口出刊判据（新增）

- **窗口 = 051 期截止 10/29 14:30 → 本期截止 10/29 15:30，约 1.0 小时**；
- **窗口内只有 2 条**（**均为媒体转述**），**但实访另拿到 1 条官方一手新条目 + 3 个挂账销项**；
- **纪律**：短窗口先核「窗口内确有硬条目」再决定出刊/挂账；**销项本身是增量**，
  **但不得把窗口外的销项包装成「窗口内新增」** —— 本期正文如实写明「窗口内仅 2 条且均为媒体转述」。
