## 这是什么

一个**每天更新**的中文情报简报，只回答一个问题：

> **今天，有哪些 AI 能力可以免费用、免费拿到、或者免费发布？**

覆盖三条线：

| 线 | 内容 | 例子 |
| --- | --- | --- |
| **免费额度** | 新上线的免费 API、免费档位变更、限免活动、Token 赠送 | 匿名模型限免一周、厂商新人免费包、平台免费档收口 |
| **免费内容生成** | 免费可用的生图/生视频/写作工具，含额度和商用条款 | 免费生成工具清单、水印与商用小字 |
| **免费内容发布** | 内容平台的 AI 分发入口、创作者招募与激励 | 平台 AI 创作能力开放、创作者计划 |

**为什么值得单独做一份**：这类信息的**价值全在时效**，而它同时散落在官方公告、模型卡、平台招募页、
社区帖子和二手聚合器里；更麻烦的是**同一个词在不同平台指的是不同东西**（"免费"有的指零价格、有的指
限时试用、有的指不限量但会留存数据）。本仓库的定位就是把这些**逐条核实、写清口径、标好截止日期**。

## 每期长什么样

固定十节结构，方便你只看关心的那几节：

```
摘要（3 秒版）           ← 只想扫一眼就看这节
一、AI 免费内容发布        ← 分发入口线
二、免费内容生成工具
三、常驻免费额度与 API     ← 长期有效的免费档，不是限时活动
四、限时活动与截止时间表   ← 带状态色条 + 可按状态筛选（网页版）
                          （047 期起移到九章之后：正文先读完，大表不挡路）
五、本期纠错清单           ← 上一期哪里写错了
六、避坑提示               ← 编号跨期连续，不重置
七、按任务选型速查
八、本期信源体系更新
九、来源与核查说明
```

几处刻意的设计：

- **只做增量**：已固化的条目不再复述，否则越写越长、越写越像目录。**防重复由脚本把关**（见下文）。
- **纠错清单是固定的第五节**：写错就明写"上一期这里不对"，不悄悄改掉。
- **避坑编号跨期连续**：第 006 期从 21 起编，接着第 005 期的 16–20。这样任何一条都能被单独引用。
- **截止时间表标三态**：🟢 生效中 / 🟠 今天换挡 / ○ 已结束，并显式标出「口径存疑」的行。
- **同一批数据，三个视图**：日报回答「这一期变了什么」，[《免费速查》](quick.html) 回答「我现在能白拿什么」（62 条，一条一行，只写给什么 / 能拿多少 / 到期日 / 门槛），[《常驻权益总账》](standing.html) 回答「这家长期还给不给」。**三个页面顶部同一位置都有一条三格切换器**（极速视图 / 完整日报 / 常驻总账），当前页实心高亮，任何一页都能一步到另外两页 —— 不用记哪个文件对应哪件事。
- **日报只报「变了什么」，不全量重印**：没有确切截止日的长期权益（131 条）单独成册在《常驻权益总账》里。理由很实在 —— 这些条目每期一个字都不变，逐期重印一遍会让正文多出六万字，把真正有时效的内容淹掉。**未重印 ≠ 未复核**，每期仍逐条过状态与口径。
- **多站点口径必须拆开写**：同一家厂商的国内站与国际站、新老平台，绝不合并成一句。

## 信源分级路由

本仓库维护一份 **182 条**的信源台账，按可信度与用途分五级。**T4 只当入口，T0 才是事实来源**：

| 层级 | 条数 | 定位 | 在报告里的用法 |
| --- | --- | ---: | --- |
| **T0** | 97 | 官方一手 / 论文 / 模型卡 / 政策 / 评测榜 | **唯一的事实来源**，数字必须回到这里核 |
| **T1** | 19 | 社区与社交（一手爆料、实测帖） | 发现线索，需回 T0 验证 |
| **T2** | 18 | Newsletter（人工筛选过的合集） | 补充视角与遗漏 |
| **T3** | 36 | 媒体（国内外科技媒体） | 交叉验证、取背景 |
| **T4** | 12 | 聚合器与工具（二手汇总） | **只当扫描入口**，不作引用来源 |

台账同时对每个源统计**命中情况**：全部 182 条里，**58 条**实际被引用过、**124 条零命中**。
这份统计不是用来吹覆盖量的（它统计的是「品牌被提及」，不等于「实际取料」），
而是用来**发现自己的盲区** —— 比如 T2 有 94%、T3 有 92% 从未被引用，
说明这两层的检索方式还有问题。台账还专门记录**清单缺口**：本期实际用到但清单里还没有的源。

## 工具链：把「不能凭估」变成脚本

日报里所有能和过去对不上的数字，都必须**由脚本核对**，不靠人眼。14 个脚本全部支持
**不传参自动取最新一期**，不需要改路径。

```bash
python .workbuddy/run_all.py            # 一把跑完 build + probe + verify（日志是干净的 UTF-8）
python .workbuddy/split_ledger.py       # 出刊前：第四章拆 4.1/4.2 + 重建《常驻权益总账》
python .workbuddy/build_quick.py        # 生成《免费速查》；--check 体检漏登
python .workbuddy/build_web.py          # 编译最新一期 → 单文件网页版
python .workbuddy/build_web.py 常驻权益总账.md standing.html   # 总账页
python .workbuddy/verify_web.py         # 必跑：判定 ALL GREEN 才继续
python .workbuddy/check_views.py        # 必跑：极速/完整/总账三页是否同构（推送前须 ALL GREEN）
python .workbuddy/check_tables.py       # 出稿后：逐表核对列数 + 避坑编号跨期连续
python .workbuddy/check_frozen.py       # 出刊前：比对已固化条目，有重复直接 exit 1
python .workbuddy/check_deadlines.py    # 出刊前：巡检过期未更新 / N 天内到期
python .workbuddy/build_index.py        # 出刊后：重建期号索引
python .workbuddy/probe_mobile.py       # 改版式后：320/360/375/414 四档手机视口量测
python .workbuddy/snap_mobile.py        # 改版式后：出 11 张手机端截图
```

| 脚本 | 它防的是什么 |
| --- | --- |
| `verify_web.py` | md 与 html 的**表格列数/行数逐表比对**、文本片段保真、未闭合标签、外部引用、状态格色标数 |
| `check_views.py` | **三个视图脱钩** —— 某页漏了切换器、高亮错格、「完整日报」还指着上一期或首页、条数与 CSV/总账实算不符 |
| `check_tables.py` | **表格错行与编号断裂** —— md 里每行 `\|` 个数必须与分隔行一致；避坑编号必须跨期连续 |
| `check_frozen.py` | **重复往期** —— 每期只做增量，靠它拦住"这条上期写过了" |
| `check_deadlines.py` | **截止日期写错** —— 过期却没标"已结束"、或即将到期却没提醒 |
| `probe_layout.py` | **版式退化** —— 表格列被压成中文逐字换行、搜索框窄到输不进字、装饰大字压住正文 |
| `probe_mobile.py` | **手机端退化** —— 搜索被整个隐藏、触控目标小于 40px、横滑时首列滚走、窄屏横向溢出 |
| `snap_mobile.py` | 手机端**视觉回归** —— iframe 造窄视口出图，靠 md5 判断镜头之间是否真的拍出了差异 |
| `audit_color.py` | **配色语义混淆** —— 两个不同语义用了同一个颜色、小字对比度不达 AA |
| `build_source_hits.py` | 台账与正文脱钩 —— 命中情况每次从正文重建，**幂等**（连跑字节一致） |

> UI 审查一律**量 DOM 不量截图**：把指标写进 `document.title` 再用无头浏览器 `--dump-dom` 抓回。
> 判据都带阈值（例如"首列过窄"要同时满足：实宽 < 140px + 行高 > 130px + 内容 ≥ 4 字真文字 + 满足度 < 90%），
> 否则会把「`#` 序号列天生就窄」这类正常情况误报成缺陷。
>
> 手机视口**不能**用 `--window-size` 直接量：Windows 下 Edge/Chrome 有约 490px 的最小窗口宽度，
> 设 320 / 375 / 414 会被静默抬到 489，三档数字一模一样。两个探针都改用 **iframe 造窄视口**，
> 媒体查询按 iframe 宽度求值才是真的手机版式。

## 三、质量是怎么保证的

每期发布前，下面的检查项必须**全部通过**：

| 检查 | 判定标准 |
| --- | --- |
| 内容保真 | `verify_web.py` 输出 `VERDICT: ALL GREEN`（表格逐表一致、缺失片段 0、外部引用 0） |
| 防重复 | `check_frozen.py` 高危 0 条，`exit 0` |
| 表格与编号 | `check_tables.py` 表格异常 **0 个**，避坑编号跨期连续 |
| 截止日期 | 过期未标的 **0 条**；对账后条目数与 CSV 一致 |
| 版式 | 桌面 1440 / 1024 与窄屏 560 无横向溢出、无首列逐字换行；**手机 320 / 360 / 375 / 414 四档**同样无溢出，触控目标 ≥ 40px，横滑表格首列粘住 |
| 配色 | 语义色色距全部 ≥ 40；WCAG AA 4.5 全过 |
| 编号连续 | 避坑编号接着上一期编，不重置 |

## 怎么读

- **只想扫一眼** → 每期开头的「摘要（3 秒版）」，6 条以内讲完当天最重要的事。
- **只想看「现在有什么免费、到什么时候结束」** → 直接开 **[《免费速查》](quick.html)**，62 条一条一行，不用读日报。也可以先读日报，再点顶部切换器随时换过去。
- **想找能用的东西** → 「四、限时活动与截止时间表」（在正文之后）看限时的，「[常驻权益总账](standing.html)」查长期的；网页版都能按状态筛。
- **怕踩坑** → 「六、避坑提示」编号跨期连续，可以单条引用。
- **想核实** → 「九、来源与核查说明」写明每条结论回到哪个 T0 源。
- **要引用某一期** → 用期号，别用"最新一期"。期号是稳定标识。

## 说明与边界

- **这是一份人工核实过的情报整理，不是投资、法律或商业决策建议。** 厂商条款与额度随时会变，
  **请以官方页面为最终依据**；报告里已尽量标注原文出处与复核时间。
- **免费不等于无成本**。报告会区分「零价格」「限时试用」「不限量但留存数据」这几种不同的"免费"，
  并在需要处写明条款分叉点。
- 本仓库内容持续更新，**不提供任何形式的准确性担保**；发现错误欢迎提 Issue 指正。
